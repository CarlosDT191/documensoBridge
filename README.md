# GLPI Documenso Signer Plugin

![GLPI](https://img.shields.io/badge/GLPI-10.0+-v?color=005f9e)
![Documenso](https://img.shields.io/badge/Documenso-Compatible-black?logo=documenso)
![License](https://img.shields.io/badge/License-GPL%20v3-blue.svg)

An open-source plugin for GLPI that seamlessly integrates with **Documenso** to automate document signing workflows directly from GLPI Tickets using specific tags.

## Features

* **Tag-Driven Automation:** Trigger signing flows automatically by adding specific tags to ticket documents.
* **Dynamic Role Mapping:** Automatically detects and assigns signers based on GLPI Ticket roles (Observer or Requester).
* **Precise Signature Placement:** Configure exact X/Y coordinates for signature placement directly from the GLPI interface.
* **Secure API Integration:** Environment-isolated server credentials combined with encrypted GLPI database storage for API Keys.

## Prerequisites

Before installing the plugin, ensure the following requirements are met:

- GLPI **10.0** or higher.
- A running **Documenso** server.
- A valid **Documenso API Key** with permissions to create signature requests.
- Network connectivity between the GLPI server and the Documenso instance.

---

## Installation

1. Copy the plugin directory into the `marketplace/` folder of your GLPI installation.
2. Install the PHP dependencies if required.
3. Rename the `.env.template` file to `.env` and configure its values.
4. Enable and install the plugin from **GLPI → Setup → Plugins**.
5. Open the plugin configuration page and complete the required settings.

## Configuration

The plugin requires two different configuration sources.

### 1. Environment Configuration (.env)

The `.env` file contains the information required to communicate with the Documenso server.

Example:

```env
DOC_SERVER=https://documenso.example.com
DOCUMENSO_CREATE=/api/v2/...
DOCUMENSO_RECIPIENT=/api/v2/...
DOC_FIELD=/api/v2/...
DOC_DISTRIBUTE=/api/v2/...
````

The exact endpoint names may vary depending on the deployed version of Documenso.

This separation allows infrastructure-related settings to remain outside the plugin configuration while simplifying deployment across different environments (development, staging and production).

---

### 2. Plugin Configuration (GLPI)

Inside the plugin configuration page, the administrator must configure:

| Setting              | Description                                                                    |
| -------------------- | ------------------------------------------------------------------------------ |
| API Key              | API Key generated by the Documenso server.                                     |
| Page number          | Page number linked to the signature position.                                  |
| Signature Position X | Horizontal coordinate where the signature field will be placed.                |
| Signature Position Y | Vertical coordinate where the signature field will be placed.                  |
| Height value         | Height of the signature field.                                                 |
| Width value          | Width of the signature field.                                                  |
| Observer Tag         | Tag name used to obtain the information from the observer user of the Ticket.  |
| Requester Tag        | Tag name used to obtain the information from the requester user of the Ticket. |

The API Key is securely stored by the plugin and is used for every request sent to the Documenso server.

## Usage Guide

The signing workflow must be completed manually according to the tag used.

### Signing by Requester

1. Create or open an existing GLPI Ticket.
2. Assign a **Requester** to the ticket.
3. Upload the document to the ticket.
4. Add the configured **Requester Tag** to the uploaded document.
5. The plugin detects the tag and retrieves the Requester's information.
6. A signing request is created in Documenso.
7. The signature field is placed on the document using the configured coordinates.
8. The Requester receives the signing request from Documenso and via email.

---

### Signing by Observer

1. Create or open an existing GLPI Ticket.
2. Assign an **Observer** to the ticket.
3. Upload the document.
4. Add the configured **Observer Tag**.
5. The plugin retrieves the Observer information.
6. The document is sent to Documenso.
7. The signature request is generated.
8. The Observer receives the invitation to sign the document.

---

## How the Plugin Works

When a document is uploaded to a GLPI Ticket, activates the plugin and process the document tag.

If one of the configured signing tags is found, the plugin determines which ticket role should become the signer:

* **Observer Tag** → Uses the Ticket Observer information.
* **Requester Tag** → Uses the Ticket Requester information.

From the selected user, the plugin retrieves the required information, including:

* Full name
* Email address

Using this information, the plugin performs the following sequence:

1. Uploads the document to Documenso.
2. Creates the document resource.
3. Creates the signature request.
4. Adds the signer as recipient.
5. Places the signature field using the configured X/Y coordinates.
6. Sends the signing invitation through Documenso.

If the document lacks a valid tag, the signing workflow will not activate.
---

## Signature Coordinates

The signature field location is configurable from the GLPI administration panel.

The configured coordinates determine where the signature box will appear on the generated document inside Documenso.

This allows administrators to adapt the plugin to different document templates without modifying the source code.

## Security Considerations

* Sensitive connection information is stored in the `.env` file.
* The Documenso API Key is managed from the plugin configuration.
* Communication with Documenso should always use HTTPS.
* Access to the plugin configuration should be restricted to GLPI administrators.

---

## Error Handling

The plugin validates several conditions before creating a signing request:

* A supported tag must exist.
* The ticket must contain the corresponding Requester or Observer.
* The selected user must have a valid email address.
* The Documenso server must be reachable.
* A valid API Key must be configured.
* Signature coordinates must be defined.

If any validation fails, the signing process is aborted and the corresponding error is logged.
